# QQMailChat 多设备邮件路由方案

**审核稿** · 2026 年 11 月 28 日

多台电脑可以共用一个 QQ 邮箱。在 `[AICHAT]` 前加 `[office-pc]` 就能指定办公室电脑。省略设备名时，各台监听器都会按原规则处理这封指令。设备名在每台电脑上单独设置。

## 1. 现状与问题

QQMailChat 安装的技能名是 `qq-mail-notify`。它通过 SMTP 发送 Codex 完成通知，通过本机 IMAP 监听器收取邮件，并用本机 Codex App Server 发起或继续会话。现有主题 `[AI会话][工作目录][会话名]` 和 `[AI会话][会话ID]` 只描述会话。同一封邮件在办公室电脑和家里电脑都可能通过校验并执行。两边都找不到同名会话时，还可能分别新建会话。 [技能说明](skills/qq-mail-notify/SKILL.md) · [会话定位](codex_qq_inbox.py#L517)

收件箱以只读方式打开，读取使用 `BODY.PEEK`。每台电脑各自保存 UID 游标、提交记录、回复关联和进程锁。用同一个 QQ 邮箱登录的监听器可以分别扫描同一封邮件，现有 `Message-ID` 去重只在本机生效。监听器优先连接本机 Codex 服务，连接失败时可启动本机 App Server，所以设备标记选中的是当前 Windows 用户和 `CODEX_HOME` 下的会话环境。 [收件与游标](codex_qq_inbox.py#L379) · [提交去重](codex_qq_inbox.py#L580) · [本机服务连接](codex_qq_inbox.py#L175)

## 2. 发信时怎么选电脑

例如，办公室电脑配置 `office-pc`，家里电脑配置 `home-pc`。所有指令仍发到同一个 QQ 邮箱。

| 操作 | 邮件主题示例 |
| --- | --- |
| 在办公室电脑按目录和名称定位或新建会话 | `[office-pc][AICHAT][工具目录][构建排查]` |
| 在家里电脑按名称使用 `Global` 会话 | `[home-pc][AICHAT][构建排查]` |
| 按完整 ID 继续办公室电脑的已有会话 | `[office-pc][AICHAT][01234567-89ab-4def-8123-456789abcdef]` |
| 省略设备名，按原规则处理 | `[AICHAT][工具目录][构建排查]` |
| 接着上一轮聊 | 直接回复收到的邮件，保留客户端生成的 `Re:` 或 `回复：` 以及原主题 |

设备名可用 1–32 个汉字、英文字母、数字或连字符，首尾用汉字、字母或数字。比如 `office-pc` 或 `办公室`。英文字母忽略大小写。`AIChat`、`AI会话` 和 `完成通知` 是保留名称。同一邮箱下各台电脑应使用不同的设备名。

第一段若为 `[AICHAT]` 或 `[AI会话]`，直接按原主题语法解析。第一段若是设备名，第二段必须是 `[AICHAT]` 或 `[AI会话]`。`[AICHAT]` 继续接受任意大小写，会话名、工作目录和完整会话 ID 的解析规则照用。旧版只识别以指令标记开头的主动指令，所以带设备名的短格式需要目标电脑先升级。 [旧版主题解析](codex_qq_inbox.py#L38)

## 3. 监听器如何决定是否执行

监听器先识别自动邮件、主动指令和回复。主动指令有设备名时，先与本机设备名比较。匹配或者省略设备名时，再按原规则校验发件人、定位本机会话并提交。跳过发给其他设备的邮件时，只推进本机 UID 游标。收件箱仍为只读，各台电脑可各自读取同一封邮件。

| 邮件情况 | 本机处理方式 |
| --- | --- |
| 主动指令的设备名匹配本机 | 校验通过后按工作目录、会话名或本机完整 ID 提交。会话忙时按现有规则排队。 |
| 主动指令未写设备名 | 直接进入原有处理流程。每台在线监听器及之后恢复轮询的监听器都可能执行同一封邮件。只想在一台电脑执行时，请写设备名。 |
| 设备名与本机不匹配、格式无效，或本机未设置设备名 | 本机跳过带设备名前缀的指令。若没有任何设备匹配，也就没有失败回执。 |
| 发件人校验通过，但目标会话或工作目录无法定位 | 沿用现有失败回执。若指定的完整 ID 在本机不存在，返回找不到会话。 |
| 自动完成邮件、自动回信或身份校验失败 | 不触发 Codex 轮次。非目标电脑也不会发回执。 |

QQ 邮箱发给自己时，用相同的本机路由配置解析收件箱邮件和「已发送」中的副本，再比对两者。外部主动指令与回复沿用各自的身份校验规则。同一封邮件的 `Message-ID` 继续由本机 SQLite 和进程锁去重。 [发件身份校验](codex_qq_inbox.py#L412) · [失败回执](codex_qq_inbox.py#L678)

上线时可以用 `check` 核对每台电脑的设备名。若两台电脑误用同一个名字，两台都有可能执行同一封带名前缀的邮件。设备离线期间，只要已经建立收件起点、邮件仍在收件箱且 `UIDVALIDITY` 没有变化，恢复监听后就会从本机游标继续读取。首次运行以及 `UIDVALIDITY` 变化后，现有逻辑会按当前收件箱建立新起点。 [收件起点](codex_qq_inbox.py#L800)

## 4. 完成通知与直接回复

| 邮件 | 发出的主题示例 |
| --- | --- |
| Codex 本机任务的完成通知 | `[office-pc][完成通知][工具目录][构建排查][续聊码 …]` |
| 主动指令完成后的回信，或失败回执 | `Re: [office-pc][AICHAT][工具目录][构建排查]` |

本机已设置设备名时，完成通知和回信都会带上设备名。来信已有匹配的设备名时，回信保留原前缀。未设置设备名时沿用原主题格式。成功回信和失败回执继续保留 `In-Reply-To` 和 `References`。由于无设备名前缀的指令可能由多台电脑处理，每封回信在登记时生成并保存自己的 `Message-ID`，同一封回信重试时沿用该值。完成通知继续生成续聊码。

1. 有回复前缀或回复头的邮件进入续聊流程。主题若有设备名，先检查是否与本机匹配。只有能关联到本机已有会话的回复才会继续。
2. 在本机回复表按邮箱、原收件地址和 `In-Reply-To` 查找。缺少 `In-Reply-To` 时查 `References`，结果须唯一指向一个会话。主题带设备名时，匹配的登记记录也要有同一设备名。原收件人仍须通过身份校验。
3. 两种回复头均缺失时，用完整主题和本机已签发的续聊码做唯一匹配。普通指令的自动回信没有续聊码时，客户端需要保留回复头。

旧的无设备名前缀通知仍可凭本机已有的邮件头关联或续聊码续聊。要改在另一台电脑执行，或给设备更名后继续旧会话，可以用当前设备名和目标电脑上的完整会话 ID 另发一封指令。失败回执也可通过改正后另发指令处理。 [回复关联与发信](codex_qq_mail.py#L240)

## 5. 在每台电脑上设置设备名

新安装时，建议在收信 `setup` 中增加「本机设备名」输入项，填 `office-pc` 或 `办公室` 即可。设备名由自己取，本机配置与 Windows 电脑名称独立。设备名可选，留空时仍处理无设备名前缀的指令。

对已有安装，方案拟增加 `route --device-name`，可设置或更改本机设备名。变更前先停止监听，设置后运行 `check`，确认显示预期设备名，再启动监听。该命令只改设备名，无需重新输入邮箱授权码。以下为实现后的用法。

```powershell
$codexProfile = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$inbox = Join-Path $codexProfile 'qq-mail\codex_qq_inbox.py'
python -I -X utf8 $inbox route --device-name office-pc
python -I -X utf8 $inbox check
python -I -X utf8 -u $inbox run
```

在家里电脑运行同一组命令，把 `office-pc` 改成 `home-pc`。设置保存为本机 `qq-mail/inbox-settings.json` 中的 `"device_name": "office-pc"`。收信监听器和发信 Hook 共用这一项。重新运行 `setup` 或更新 IMAP 凭据时保留现有设备名，`check` 和监听启动日志显示设备名及本机配置路径。 [安装更新逻辑](install.py#L88) · [IMAP 凭据保存](qq_mail_credentials.py#L47)

上线时，先让旧监听器处理完在途任务和回执，再依次升级并给每台电脑设置设备名。已有安装沿用游标。新安装等到「已记录收件起点」再发测试邮件。升级后可直接用旧格式发送不指定设备的指令。

## 6. 验收与审核

| 场景 | 应看到的结果 |
| --- | --- |
| 两台电脑同时监听，轮流指定不同设备，且两边存在同名会话 | 每封邮件只在指定设备的目标会话产生一轮，只有该设备回信。 |
| 两台电脑同时监听，收到无设备名前缀的主动指令 | 两台都按原规则处理。若同一指令产生两封回信，各有自己的设备名和 `Message-ID`，直接回复其中一封只续聊它对应的会话。 |
| 设备名拼错、格式无效、大小写不同，或本机未设置设备名 | 拼错和格式无效时无轮次、无回执。有效设备名的英文大小写不影响匹配。未命名的本机只处理无设备名前缀的主动指令。 |
| 旧版解析器收到带设备名的短格式指令 | 旧版不把带前缀的主题当作主动指令。原来的无前缀主题仍按原语法解析。 |
| 设备正确但本机没有指定会话 ID，或发件人未授权 | 前者由目标设备发一封失败回执，后者无轮次、无回执。 |
| QQ 邮箱发给自己，或从允许列表中的外部邮箱发指令 | 分别通过已发送副本比对或现有外部身份校验，两种方式都只在目标设备执行。 |
| 直接回复成功邮件或旧的完成通知、手工改设备名、客户端省略回复头 | 正常回复回原会话。修改主题中的设备名不会把回复转给另一台电脑。无回复头时，可用已签发且能唯一匹配的续聊码继续。 |
| 目标电脑重启、重复收到同一 `Message-ID`、另一台电脑持续在线 | 目标电脑从本机游标恢复，成功提交一次。另一台电脑保持零轮次。 |
| 设置设备名后更新凭据、重启监听，或在本机更改设备名 | 更新凭据和重启后显示原设备名。更名后，新指令和新通知使用新设备名。 |

自动化验收用两个独立本地状态库模拟同一收件箱。实施后用两台实机验证 QQ IMAP 并发登录，以及 QQ 邮箱客户端能否保留回信的主题和邮件头。本稿供审核，设备名设置命令及邮件分流规则将在实现后生效。
